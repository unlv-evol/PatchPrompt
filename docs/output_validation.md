# Output Validation

Validation is controlled by `replication/expected_outputs.yaml` and implemented in `replication/verify_outputs.py`.

## Validation modes

Supported validation modes:

- `exists`: artifact must exist;
- `nonempty`: artifact must exist and have nonzero size;
- `csv_schema`: artifact must be a readable CSV and contain the listed required columns.

Generated manifests are written to `results/manifests/` with artifact paths, byte sizes, and SHA-256 hashes.

## RQ1 validation outputs

The Section 4.1 annotation-reliability outputs are explicitly checked by `make verify`:

```text
results/rq1/rq1_overall_agreement_metrics.csv
results/rq1/rq1_class_conditioned_kappa.csv
results/rq1/rq1_annotation_policy.csv
results/rq1/rq1_human_llm_validation_pairs.csv
```

The expected schemas are:

```text
rq1_overall_agreement_metrics.csv:
Dimension, Quadratic_Weighted_Kappa, MAE, Directional_Bias

rq1_class_conditioned_kappa.csv:
Class, N, kappa_C, kappa_S, kappa_V

rq1_annotation_policy.csv:
Metric, PA, PN, CL, NE

rq1_human_llm_validation_pairs.csv:
Case_ID, Classification, Human_Context, Human_Specificity, Human_Verification,
LLM_Context, LLM_Specificity, LLM_Verification
```

The RQ1 values should reproduce the manuscript-level results:

- Context overall κ = 0.526, MAE = 0.463, bias = -0.439;
- Specificity overall κ = 0.431, MAE = 0.317, bias = -0.195;
- Verification overall κ = 0.291, MAE = 0.354, bias approximately -0.061;
- Table 1 per-class κ values for PA, PN, CL, and NE;
- Table 2 class-aware annotation policy.

## Interpretation

A successful `make verify` confirms that required artifacts exist and conform to expected schemas. It does not assert scientific validity by itself; the scripts and notebooks provide the transparent computation paths used to generate and inspect those outputs.


## Full robustness and sensitivity outputs

The package includes an expanded robustness layer for the stage-based models. These outputs are generated by `analysis/diagnostics/robustness_sensitivity_outputs.py` and validated by `make verify`. The checks include:

- dominant-repository exclusion, using the most frequent repository within each gate-specific modeling sample;
- extreme pull-request size exclusion, using the 95th percentile PR-size cutoff within each gate-specific modeling sample;
- dominant-language exclusion, using the most frequent programming language within each gate-specific modeling sample;
- aggregate PQS specifications compared against the main individual-dimension models using Context, Specificity, and Verification.

Generated files are written to `results/diagnostics/`, including `full_robustness_sensitivity_results.csv`, `dominant_repository_exclusion.csv`, `extreme_pr_size_exclusion.csv`, `dominant_language_exclusion.csv`, `pqs_vs_dimension_models.csv`, and `robustness_sensitivity_summary.md`.

## Diagnostic Plots and Summary Validation

The replication package now validates both tabular and visual diagnostics under
`results/diagnostics/`. In addition to CSV diagnostics, `make verify` checks that the
following generated artifacts exist and are nonempty:

- `results/diagnostics/diagnostics_summary.md`
- `results/diagnostics/vif_diagnostics.png`
- `results/diagnostics/vif_correlation_heatmap.png`
- `results/diagnostics/schoenfeld_residual_plots/*.png`

These artifacts provide visual and narrative support for the paper's diagnostic claims:
no severe multicollinearity, no complete/quasi-separation in the primary logistic
models, and no severe proportional-hazards violations in the lifecycle models.


## Qualitative Illustrative Evidence

The package includes a traceable qualitative evidence dataset at `results/qualitative/illustrative_examples_dataset.csv`. It extracts the full canonical records for the paper-referenced illustrative cases used in the stage-based qualitative discussion, including PN-19, NE-3, PA-22, PA-78, and PA-24. A companion markdown summary is available at `results/qualitative/illustrative_examples_summary.md`, and the selection process is documented in `notebooks/illustrative_examples_walkthrough.ipynb`.

## Additional Validation Targets

The expected-output specification now also checks the final reproducibility-support artifacts:

- runtime environment JSON files,
- runtime benchmark CSVs,
- frozen environment snapshots,
- reproduction report,
- provenance manifest and SHA256 checksum file,
- selected PDF table export,
- Docker reproduction documentation,
- methodological-alignment diagnostics outputs.

These checks ensure that the replication package contains not only the scientific results but also the environment, provenance, and evaluator-support artifacts needed for robust artifact review.
